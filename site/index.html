Install. Run. Control.

One global install provides the local angysguard command. It creates an isolated runtime and never asks for your OS password.

Then run angysguard doctor before enabling or relying on features.

What you can use today

Support is feature and environment specific. Run Doctor on the protected device before relying on camera, audio, input, screen, session, service, or provider capabilities.

How AngysGuard works

The protection path is intentionally observable and bounded: no silent surveillance, no generic command channel, and no OS password transport through chat or a backend.

Observe configured local signals.
Classify and record a local event.
Collect only bounded evidence where enabled.
Notify the verified owner through the chosen surface.
Show visible warning and lock when local policy requires.

Install and run on Linux

Install the npm terminal package for the fastest path, or use the repository installer when you want to work from source. Both paths are Linux-only and create a local Python environment without sudo.

1. Configure locally

Choose local, Bale, or Telegram-style provider. Enter tokens only in the local prompt; never in a chat, screenshot, issue, or repository.

2. Pair the owner

Pair only your private owner chat. Group/channel updates and ambiguous identities are rejected for privileged controls.

3. Verify readiness

Run Doctor and focused hardware/provider tests. Automated tests cannot prove your camera, desktop session, network, or live provider setup.

The npm package remains experimental. It requires Linux, Node.js 20+, Python 3.11+, network access for Python dependencies, and a successful local Doctor result.

Control surfaces, without giving up safety

Local dashboard

Setup, protection state, profiles, Doctor, events, service and autostart controls are available from ./run.sh.

Owner bot menu

The paired owner can review dashboard, protection, incidents, bounded evidence, device health and settings using fixed controls.

Profiles and input policy

New local setup warns without locking. Away and Night explicitly use warning-then-lock, while Home and Testing never auto-lock from input.

Security and privacy are product boundaries

Owner authorization

Privileged bot actions require a verified private owner identity. Sensitive operations can be confirmation-gated or locally opted in.

Explicit and bounded evidence

Capture is feature-dependent, explicit, bounded by policy, and retained locally under configured limits. It is not stealth recording.

No dangerous shortcuts

No generic remote shell, arbitrary filesystem control, credential collection, keylogging typed content, or OS password transfer through Bale, Telegram, apps, or backend.

Frequently asked questions

Can I use it on Windows today?

No supported Windows protection release exists today. Windows work remains planned/managed-test source and needs native capability completion plus Windows 10/11 target-device validation.

Can multiple computers share one self-hosted bot token?

No. Independent local runtimes can compete for the same provider updates. Use separate bots/tokens today; managed multi-device control is future work.

Does a VPN or proxy belong in setup?

If your provider requires it, configure the explicit proxy URL in the local setup prompt. Keep bot tokens private and validate connectivity with Doctor after setup.
